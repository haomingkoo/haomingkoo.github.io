Japan in Seasons

A map and an MCP server that tell travellers, and the AI assistants they use, when and where cherry blossoms, autumn leaves, flowers, festivals and fruit picking are happening across Japan.

Open live app Source on GitHub

TypeScript, Node.js and the MCP SDK, deployed on Railway and published on npm and Smithery.

The problem

Bloom and foliage timing shifts by days each year and differs from city to city. A language model answers from its training data, so a question like “where are the leaves at their best next week?” gets a stale or invented answer.

What it does

The web map shows the current status and forecast for each spot. The same data is served as an MCP server with 17 read-only tools, including sakura_now, koyo_forecast, festivals_list and weather_forecast, so Claude or any MCP client can answer from today's forecast.

It runs locally with npx japan-seasons-mcp or as a hosted server at seasons.kooexperience.com/mcp, which needs no sign-in.

How it works

  • Refreshed when the source publishesJapan Meteorological Corporation publishes at 9 AM JST. The cache flushes then and preloads forecasts and spots, so the first visitor after a publish gets fresh data without waiting.
  • One rule for which source to trustA reporter's on-site observation wins if it was filed in the last 48 hours. After that the app falls back to the forecast estimate and shows the older observation as context.
  • Safe for agents to callEvery tool is annotated readOnlyHint and idempotentHint, so a client knows a retry cannot change anything.

What was hard

Building the nationwide spot list takes one upstream request per prefecture. The result is cached and shared across users, concurrent refreshes collapse into a single request, a file cache carries it across restarts, and unused fields are stripped before it is sent to the browser.

Results

The map is live, and the MCP server is published on npm as japan-seasons-mcp and listed on Smithery. The build notes cover how I worked through Smithery's quality checks.
